Core Architectural Principles

Three Distinct Pillars: Programs ≠ Store ≠ Hub

KuroLabs enforces clear architectural boundaries. We never conflate standalone applications, runtime capability managers, and remote decentralized registries.

01

Programs

Complete Software Applications

Independent software products with their own repositories, releases, documentation, and lifecycle. Flagship: KuroCodeAgent.

  • • Standalone CLI & GUI executables
  • • Autonomous agent cognitive core
  • • Local DPAPI credentials & SQLite memory
Browse Programs Directory →
02

The Store

KuroCodeAgent Runtime Manager

The internal subsystem inside KuroCodeAgent responsible for discovering, resolving, and hot-installing capabilities dynamically.

  • • Runtime commands: /hub install (or /store install)
  • • Resolves dependencies into local agent
  • • Zero browser execution — pure terminal runtime
View Store Runtime Docs →
03

Capability Hub

Remote Registry Repository

The open GitHub repository (kurolabs-ai/hub) maintaining the kuro-hub.json and standalone capability files.

  • • Standalone tools, plugins & skills
  • • Clean JSON metadata schema
  • • Decoupled from any single frontend
